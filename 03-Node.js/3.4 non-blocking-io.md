# Non-Blocking I/O in Node.js

# What is I/O?

I/O stands for:

```text
Input / Output
```

It means any operation where data is:
- Read (Input)
- Written (Output)

Examples:
- Reading a file
- Writing to database
- API request
- Network call

---

# What is Blocking I/O?

Blocking I/O means:

```text
Code waits until operation is completed
```

---

## Example (Blocking)

```js
const fs = require("fs")

const data = fs.readFileSync("file.txt")

console.log(data)

console.log("Next line")
```

---

## Output

```text
(file content)
Next line
```

---

## Problem

- Execution is paused
- Other tasks cannot run
- Bad for performance

---

# What is Non-Blocking I/O?

Non-blocking I/O means:

```text
Code does NOT wait for operation to finish
```

It continues executing other tasks.

---

## Example (Non-Blocking)

```js
const fs = require("fs")

fs.readFile("file.txt", (err, data) => {
   console.log(data)
})

console.log("Next line")
```

---

## Output

```text
Next line
(file content)
```

---

# Key Difference

| Blocking I/O | Non-Blocking I/O |
|---|---|
| Waits for task | Does not wait |
| Slower | Faster |
| Sequential | Concurrent |
| Poor scalability | High scalability |

---

# How Non-Blocking I/O Works in Node.js

Node.js uses:

- Event Loop
- Libuv
- Callback Queue
- Thread Pool

---

## Flow

```text
Request
 ↓
Node.js
 ↓
Send to background (libuv)
 ↓
Main thread continues
 ↓
Task completes
 ↓
Callback executed
```

---

# Internal Working

## Step 1

Request arrives.

---

## Step 2

Node sends task to:
- Thread pool (if heavy)
- OS kernel (if I/O)

---

## Step 3

Main thread continues execution.

---

## Step 4

Task completes in background.

---

## Step 5

Callback is pushed to event loop.

---

## Step 6

Event loop executes callback.

---

# Example with Timer

```js
console.log("Start")

setTimeout(() => {
   console.log("Timer Done")
}, 2000)

console.log("End")
```

---

## Output

```text
Start
End
Timer Done
```

---

# Why This Happens?

Because:
- setTimeout is non-blocking
- It runs in background

# Advantages of Non-Blocking I/O

## 1. High Performance

No waiting time.

---

## 2. Scalability

Handles thousands of requests.

---

## 3. Efficient Resource Usage

Uses single thread effectively.

---

## 4. Better User Experience

Faster response time.

---

# Disadvantages

## 1. Complex Code Flow

Harder to understand async flow.

---

## 2. Debugging Difficulty

Execution order is not linear.

---

## 3. CPU Heavy Tasks Problem

Not suitable for heavy computations.

---

## Non-Blocking

- Chat systems
- Streaming apps

# Important Concept

```text
Non-blocking ≠ Parallel execution
```

It means:
- Tasks do NOT block main thread
- But still executed asynchronously

Node.js is powerful because:
