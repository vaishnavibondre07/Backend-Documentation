# Streams and Buffers in Node.js

# Why Streams and Buffers Exist?

When working with data in backend:
- Files can be very large
- Data can come continuously (video, audio, APIs)

Loading everything at once is inefficient.

So Node.js uses:
```text
Streams + Buffers
```

---

# What is a Buffer?

A Buffer is:

```text
Temporary storage of binary data
```

Node.js uses buffers to handle raw data.

---

# Simple Definition

```text
Buffer = Raw binary data stored in memory
```

---

# Example of Buffer

```js
const buf = Buffer.from("Hello")

console.log(buf)
```

---

# Output

```text
<Buffer 48 65 6c 6c 6f>
```

---

# Why this output?

Because:
- Data is stored in binary (ASCII/UTF-8 format)

---

# Real Life Analogy

Buffer is like:

```text
A bucket holding water before pouring it forward
```

---

# Where Buffers are Used

- File reading
- Network packets
- Video/audio streaming
- Image processing

---

# What is a Stream?

A Stream is:

```text
A continuous flow of data
```

Instead of loading all data at once,
data is processed piece by piece.

---

# Simple Definition

```text
Stream = Data flow in chunks
```

---

# Types of Streams

## 1. Readable Stream

Used to read data.

Example:
- Reading file

---

## 2. Writable Stream

Used to write data.

Example:
- Writing file

---

## 3. Duplex Stream

Both read + write.

Example:
- TCP sockets

---

## 4. Transform Stream

Modify data while passing.

Example:
- Compression

---

# Streams Flow

```text
Source → Stream → Destination
```

---

# Example: Read File Using Stream

```js
const fs = require("fs")

const stream = fs.createReadStream("file.txt")

stream.on("data", (chunk) => {
   console.log("Chunk:", chunk)
})
```

---

# What Happens?

File is not loaded fully.

Instead:
```text
File → small chunks → processed one by one
```

---

# Advantage

- Memory efficient
- Faster processing

---

# Example: Write Stream

```js
const fs = require("fs")

const stream = fs.createWriteStream("output.txt")

stream.write("Hello World")
stream.write(" Node.js Streams")
stream.end()
```

---

# Streams vs Normal File Reading

## Normal Read

```js
fs.readFile("file.txt", (err, data) => {})
```

- Loads full file into memory

---

## Stream Read

```js
fs.createReadStream("file.txt")
```

- Loads data in chunks

---

# Why Streams are Important

Because they:
- Reduce memory usage
- Improve performance
- Handle large files easily

---

# Real World Example

## Video Streaming

YouTube does NOT download full video first.

Instead:
```text
Video loads in chunks while playing
```

---

# Buffer + Stream Relationship

Streams use buffers internally.

```text
Stream → uses Buffer → processes data chunk by chunk
```

---

# Example: Pipe Stream

```js
const fs = require("fs")

const readStream = fs.createReadStream("input.txt")

const writeStream = fs.createWriteStream("output.txt")

readStream.pipe(writeStream)
```

---

# What is pipe()?

It connects:
```text
Readable Stream → Writable Stream
```

---

# Advantages of Streams

## 1. Memory Efficient

Does not load full file.

---

## 2. Faster Processing

Works in chunks.

---

## 3. Scalable

Handles large data easily.

---

# Disadvantages

## 1. Complex Handling

More logic required.

---

## 2. Hard Debugging

Data flows continuously.

---

# Buffer Methods

## Buffer.from()

Creates buffer from string.

```js
Buffer.from("Hello")
```

---

## Buffer.alloc()

Creates empty buffer.

```js
Buffer.alloc(10)
```

---

# Stream Events

## data

Triggered when chunk arrives.

---

## end

Triggered when stream finishes.

---

## error

Triggered when error occurs.

---

# Example with Events

```js
stream.on("data", (chunk) => {
   console.log(chunk)
})

stream.on("end", () => {
   console.log("Finished")
})
```
