# REST API Basics

# What is REST?

REST stands for:

```text
Representational State Transfer
```

REST is a way to design APIs so that frontend and backend can communicate properly.

It is the most commonly used API architecture in backend development.

---

# What is API?

API stands for:

```text
Application Programming Interface
```

API acts like a bridge between:
- Frontend
- Backend

---

# Real Life Example

Imagine restaurant.

## Client

Customer gives order.

## API

Waiter takes order to kitchen.

## Server

Kitchen prepares food.

## Response

Food returned to customer.

---

# What is REST API?

REST API is an API that follows REST principles.

Example:

```http
GET /users
```

This API fetches users data.

---

# Why REST APIs are Used

REST APIs:
- Connect frontend and backend
- Transfer data
- Make applications scalable
- Allow mobile apps and websites to use same backend

---

# REST Architecture

```text
Client ---> REST API ---> Server ---> Database
```

---

# REST Principles

# 1. Client Server Separation

Frontend and backend should be separate.

Frontend:
- UI
- User interaction

Backend:
- Business logic
- Database

---

# 2. Stateless

Server does not remember previous requests.

Every request must contain complete information.

---

# 3. Uniform Interface

APIs should follow standard rules.

Example:

```http
GET /users
POST /users
DELETE /users/1
```

---

# 4. Cacheable

Responses can be cached for performance.

---

# 5. Layered System

Client should not know backend architecture.

---

# HTTP Methods in REST APIs

# GET

Fetch data.

Example:

```http
GET /products
```

---

# POST

Create new data.

Example:

```http
POST /users
```

---

# PUT

Update complete resource.

Example:

```http
PUT /users/1
```

---

# PATCH

Update partial resource.

Example:

```http
PATCH /users/1
```

---

# DELETE

Delete resource.

Example:

```http
DELETE /users/1
```

---

# REST API Endpoint Examples

| Method | Endpoint | Purpose |
|---|---|---|
| GET | /users | Get all users |
| GET | /users/1 | Get single user |
| POST | /users | Create user |
| PUT | /users/1 | Update user |
| DELETE | /users/1 | Delete user |

---

# Status Codes in REST APIs

| Status Code | Meaning |
|---|---|
| 200 | Success |
| 201 | Created |
| 400 | Bad Request |
| 401 | Unauthorized |
| 404 | Not Found |
| 500 | Internal Server Error |

---

# REST API Naming Best Practices

# Use Nouns

Correct:

```http
/users
```

Wrong:

```http
/getUsers
```

---

# Use Plural Names

Correct:

```http
/products
```

Wrong:

```http
/product
```

---

# Use Proper Resource Structure

Example:

```http
/users/1/orders
```

---

# Example REST API in Express.js

```js
const express = require("express")

const app = express()

app.get("/users", (req, res) => {
   res.json({
      success: true,
      data: ["User1", "User2"]
   })
})

app.listen(3000)
```

# Advantages of REST APIs

## 1. Simple

Easy to understand.

## 2. Scalable

Supports large applications.

## 3. Flexible

Works with:
- Web apps
- Mobile apps
- Desktop apps

## 4. Stateless

Improves scalability.

---

# Disadvantages of REST APIs

## 1. Multiple Requests

Sometimes many API calls required.

## 2. Over-fetching

May return extra data.

# REST vs SOAP

| REST | SOAP |
|---|---|
| Lightweight | Heavy |
| Uses JSON | Uses XML |
| Faster | Slower |
| Easy | Complex |
