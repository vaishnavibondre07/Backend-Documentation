# Stateless vs Stateful

# What is Stateful?

Stateful means:

Server remembers previous client information.

Server stores session/state data.

---

# Real Example of Stateful

Phone call.

Both people remember conversation history.

---

# Stateful Communication Example

```text
User Login
↓
Server stores session
↓
User sends next request
↓
Server remembers user
```

---

# What is Stateless?

Stateless means:

Server does NOT remember previous requests.

Every request is independent.

Each request must contain complete information.

---

# Real Example of Stateless

ATM machine.

Every transaction requires:
- Card
- PIN

Machine does not remember previous transaction.

---

# Stateless Communication Example

```text
Request 1 → Independent
Request 2 → Independent
Request 3 → Independent
```

---

# Example in REST APIs

REST APIs are stateless.

Every request contains:
- Token
- Authentication info
- Request data

---

# Stateful Authentication

Example:
- Session authentication

Server stores:
- User session
- Login state

---

# Stateless Authentication

Example:
- JWT Authentication

Client stores token.

Every request sends token.

---

# Stateful Architecture

```text
Client
   ↓
Server stores session
```

---

# Stateless Architecture

```text
Client sends token every request
Server verifies token
```

---

# Advantages of Stateful

# 1. Easier Session Management

Server controls sessions.

---

# 2. Better for Traditional Applications

Used in old web systems.

---

# Disadvantages of Stateful

# 1. Hard to Scale

Server memory stores sessions.

---

# 2. Session Synchronization Problems

Multiple servers must share sessions.

---

# Advantages of Stateless

# 1. Highly Scalable

No session storage needed.

---

# 2. Better Performance

Easy load balancing.

---

# 3. Simple Distributed Systems

Works well in cloud systems.

---

# Disadvantages of Stateless

# 1. Every Request Needs Authentication

Token sent every request.

---

# 2. Slightly Larger Requests

Headers contain tokens.

---

# Session vs JWT

| Session | JWT |
|---|---|
| Stateful | Stateless |
| Server stores session | Client stores token |
| Harder scaling | Easier scaling |

---

# Example of Session Authentication

```text
User Login
↓
Server creates session
↓
Session ID stored in cookie
```

---

# Example of JWT Authentication

```text
User Login
↓
JWT token generated
↓
Client stores token
↓
Token sent in every request
```

---

# Why Modern APIs Prefer Stateless

Because stateless systems:
- Scale better
- Work better with cloud
- Support distributed systems
- Easier load balancing

---

# Load Balancer Problem

# Stateful

Request must go to same server.

---

# Stateless

Any server can handle request.

---

# Real World Examples

# Stateful

- Traditional PHP applications
- Banking systems
- Online multiplayer games

---

# Stateless

- REST APIs
- Modern backend systems
- Microservices

---

# Interview Questions

## What is stateless API?

API where server does not store client state.

---

## Why REST APIs are stateless?

To improve scalability and simplicity.

---

## Difference between session and JWT?

Session stores state on server.
JWT stores token on client.

---

# Summary

Stateful:
- Server remembers client
- Session based
- Harder to scale

Stateless:
- Server does not remember client
- Token based
- Highly scalable
