# Memory Management in JavaScript

# What is Memory Management?

Memory management means:

```text
Allocating, using, and freeing memory properly.
```

JavaScript automatically manages memory.

---

# Why Memory Management is Important

Poor memory handling causes:
- Slow applications
- Crashes
- Memory leaks
- High RAM usage

---

# JavaScript Memory Lifecycle

# 1. Allocate Memory

Memory assigned to variables.

---

# 2. Use Memory

Program reads/writes memory.

---

# 3. Release Memory

Unused memory removed.

---

# Example

```js
let name = "NodeJS"
```

Memory allocated for string.

---

# Memory Types

# 1. Stack Memory

Stores:
- Primitive values
- Function calls

Fast memory.

---

# 2. Heap Memory

Stores:
- Objects
- Arrays
- Functions

Larger but slower.

---

# Stack Example

```js
let age = 20
```

Stored in stack.

---

# Heap Example

```js
const user = {
   name: "Vaishnavi"
}
```

Object stored in heap.

---

# Stack vs Heap

|        Stack      |     Heap    |
|-------------------|-------------|
|       Fast        |    Slower   |
| Primitive values  |   Objects   |
|     Fixed size    |   Dynamic   |

---

# Garbage Collection

JavaScript automatically removes unused memory.

This process is called:

```text
Garbage Collection
```

---

# What is Garbage?

Unused objects in memory.

Example:

```js
let user = {
   name: "Node"
}

user = null
```

Old object becomes garbage.

---

# Garbage Collector

JavaScript engine automatically removes unused memory.

---

# Mark and Sweep Algorithm

Most JavaScript engines use:
- Mark
- Sweep

---

# Step 1 — Mark

Reachable objects marked.

---

# Step 2 — Sweep

Unreachable objects deleted.

---

# Reachable Objects

Objects accessible from:
- Variables
- Functions
- Global scope

stay in memory.

---

# Memory Leak

Memory leak happens when:
- Unused memory is not released.

---

# Example of Memory Leak

```js
let users = []

function addUser() {

   users.push(new Array(1000000))
}
```

Memory keeps growing.

---

# Common Causes of Memory Leaks

# 1. Global Variables

```js
name = "Node"
```

Avoid accidental globals.

---

# 2. Unused Timers

```js
setInterval(() => {

}, 1000)
```

Not cleared.

---

# 3. Closures

Closures may keep variables alive.

---

# 4. Detached DOM References

Common in frontend.

---

# Memory Leak in Backend

Node.js servers run continuously.

Leaks can:
- Crash server
- Increase RAM usage
- Slow APIs

---

# Example in Node.js

```js
const cache = {}

app.get("/", (req, res) => {

   cache[req.url] = largeData
})
```

Memory grows continuously.

---

# Preventing Memory Leaks

# 1. Avoid Global Variables

Use:
- let
- const

---

# 2. Clear Timers

```js
clearInterval(id)
```

---

# 3. Remove Unused References

```js
user = null
```

---

# 4. Use WeakMap

Allows garbage collection.

---

# Memory Optimization Tips

- Use streaming
- Avoid huge arrays
- Optimize loops
- Use caching carefully

---

# Node.js Memory Tools

- Chrome DevTools
- heapdump
- Node Inspector

---

# Interview Questions

## What is garbage collection?

Automatic removal of unused memory.

---

Unused memory remaining allocated.

---

## Difference between stack and heap?

Stack stores primitives.
Heap stores objects.
