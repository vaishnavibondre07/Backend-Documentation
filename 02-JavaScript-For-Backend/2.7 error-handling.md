# Error Handling in JavaScript

# What is Error Handling?

Error handling means:

```text
Detecting, managing, and responding to errors properly.
```

Errors are common in every application.

Good backend systems must handle errors correctly.

---

# Why Error Handling is Important

Without proper error handling:
- Application may crash
- Server may stop
- Users get bad experience
- Security problems may happen

---

# Types of Errors in JavaScript

# 1. Syntax Error

Wrong JavaScript syntax.

Example:

```js
console.log("Hello"
```

Missing bracket.

---

# 2. Reference Error

Using undefined variable.

```js
console.log(name)
```

---

# 3. Type Error

Invalid operation on type.

```js
null.toUpperCase()
```

---

# 4. Range Error

Value outside allowed range.

```js
new Array(-1)
```

---

# 5. Custom Errors

Developer-created errors.

---

# What Happens When Error Occurs?

If error is not handled:
- JavaScript stops execution
- Node.js server may crash

---

# try-catch

Used to handle runtime errors.

---

# Basic Syntax

```js
try {

   // risky code

} catch (error) {

   // error handling
}
```

---

# Example

```js
try {

   const data = JSON.parse("invalid")

} catch (error) {

   console.log("Error occurred")
}
```

---

# Output

```text
Error occurred
```

---

# How try-catch Works

# try Block

Contains risky code.

---

# catch Block

Runs when error occurs.

---

# Error Object

```js
try {

   console.log(user)

} catch (error) {

   console.log(error)
}
```

---

# Error Object Properties

# name

Error type.

---

# message

Error description.

---

# stack

Error location.

---

# Example

```js
try {

   console.log(user)

} catch (error) {

   console.log(error.name)
   console.log(error.message)
}
```

---

# finally Block

Runs always.

```js
try {

} catch {

} finally {

   console.log("Always runs")
}
```

---

# Why finally is Useful

Used for:
- Closing database connection
- Cleanup tasks
- Closing files

---

# Throwing Custom Errors

```js
function divide(a, b) {

   if (b === 0) {
      throw new Error("Cannot divide by zero")
   }

   return a / b
}
```

---

# Custom Error Example

```js
try {

   divide(10, 0)

} catch (err) {

   console.log(err.message)
}
```

---

# Output

```text
Cannot divide by zero
```

# Async Error Handling

# Promise Error Handling

```js
fetchData()
   .catch((err) => {
      console.log(err)
   })
```

---

# Async Await Error Handling

```js
async function test() {

   try {

      const data = await fetchData()

   } catch (err) {

      console.log(err)
   }
}
```

# Error Handling in Express.js

# Basic Example

```js
app.get("/", (req, res) => {

   try {

      res.send("Hello")

   } catch (err) {

      res.status(500).send("Server Error")
   }
})
```

---

# Centralized Error Middleware

```js
app.use((err, req, res, next) => {

   res.status(500).json({
      success: false,
      message: err.message
   })
})
```

---

# Why Centralized Error Handling is Important

Benefits:
- Cleaner code
- Better debugging
- Standard error responses

---

# Operational Errors vs Programmer Errors

# Operational Errors

Expected errors.

Examples:
- Invalid password
- Database timeout
- File not found

---

# Programmer Errors

Code mistakes.

Examples:
- Undefined variable
- Wrong logic

# Best Practices

# 1. Never Expose Sensitive Errors

Wrong:

```js
res.send(err.stack)
```

---

# 2. Use try-catch Properly

Especially with async-await.

---

# 3. Use Centralized Error Middleware

Better architecture.

---

# 4. Validate Input

Prevent invalid data.

---

# 5. Log Errors

Use:
- Winston
- Morgan
- Console logs

# Real Backend Error Example

```js
async function login(req, res) {

   try {

      const user = await User.findOne({
         email: req.body.email
      })

      if (!user) {

         return res.status(404).json({
            message: "User not found"
         })
      }

   } catch (err) {

      res.status(500).json({
         message: "Internal Server Error"
      })
   }
}
```
